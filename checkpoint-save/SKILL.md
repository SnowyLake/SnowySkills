## 目标与边界

保存供后续读取, 续接或审查的当前状态和必要历史. 本 skill 只写当前会话文件夹中的 `CONTEXT.md` 和 `HISTORY.md`; 不修改项目文件或其他产物, 除非用户另有明确要求.

保存前读取 [checkpoint-contract.md](references/checkpoint-contract.md) 中的共享规则和文件结构. 若文件不可用, 停止并报告缺失文件, 不凭记忆重建契约.

## 会话文件夹解析

读取其他会话的 checkpoint 不会将其来源文件夹设为当前会话文件夹. 仅作为读取来源的路径不作为保存位置的候选; 用户明确指定共享文件夹作为当前会话文件夹时, 才按该指定保存.

将当前会话文件夹解析为三种状态:

- 明确有: 当前对话或用户输入已经明确指向一个当前会话文件夹. 复用它.
- 明确没有: 当前对话没有可用会话文件夹线索, 且用户请求是在创建或刷新当前 checkpoint. 创建新的当前会话文件夹.
- 不确定: 现有线索无法识别唯一当前会话文件夹, 或用户同时提到多个路径但没有标明角色. 询问用户指定已有文件夹或确认创建新文件夹.

创建新文件夹时, 使用 `.agent-sessions/{YYYYMMDD}-{short-kebab-case-session-summary}/`, 并在输出中说明新建路径.

## 保存

- 先读已有 `CONTEXT.md`, 结合当前对话和影响本次保存的项目事实确定变化. 对已有 `HISTORY.md`, 先查最近相关条目, 需要追溯时再扩大阅读, 不要求每次通读全部历史.
- 按契约的信息取舍与更新规则整合 `CONTEXT.md`, 使用 OpenCode 的七个章节组织当前快照. 清除已解决或过时内容, 保留有效要求, 决策理由, 未完成请求, 准确停点及验证范围; 用 `Relevant Files` 定位必要文件.
- 首次保存建立 `CONTEXT.md`. 仅在有值得追溯的新背景时创建或追加 `HISTORY.md`, 普通进度变化不重复写入历史. 没有实质变化时保持文件不变, 不为套用新格式改写旧快照.
- 保留已有历史条目, 包括未读取的部分; 未经用户要求不清理或重建旧历史. `HISTORY.md` 不存在是正常情况; 已有 checkpoint 缺少当前快照或有明确的信息丢失时, 仅补齐可确认的内容并说明缺失, 不虚构历史.
- 仅在本次保存有实质更新时按当前结构整理该会话快照, 不批量迁移其他 checkpoint. 写入后维护已有 TOC; 短文件无需新增 TOC.

## 完成

确认需要保存的状态和历史已写入, 文件结构及引用与本次变化一致. 若只完成部分写入, 如实说明, 不报告全部保存成功.

简要报告会话路径, 已更新文件, 关键变化和仍影响续接的未解决事项. 无实质变化时说明 checkpoint 已是最新. 默认不逐段复述快照; 用户要求完整状态时再展开.
