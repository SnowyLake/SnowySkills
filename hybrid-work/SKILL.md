# Hybrid Work

## 目录

- [启用范围](#启用范围)

## 启用范围

- 仅适用于 Codex, 使用其 `spawn_agent` 工具创建执行子代理.
- 用户调用后, 当前会话持续启用, 后续轮次和新任务无需再次调用; 任务完成或上下文压缩不使其失效. 在会话摘要中保留启用或暂停状态.
- 仅在用户明确要求暂停或停用时停止, 停止新委派并协调运行中的执行者安全停下. 用户明确恢复或再次调用后重新启用; 暂停委派不等于取消原任务.
- 保留当前主代理负责需求, 关键决策与验收, 将有明确交付物的实质性执行工作交给子代理. 简单步骤或交接成本高于收益时直接完成; 这不改变启用状态.
- 启用期间仍可按需调用其他子代理承担独立设计, 调查或审阅; Sol 执行子代理负责实现, 调试与验证, 不限制其他子代理的使用.

## 动态委派

- 动态创建执行子代理, 默认模型为 `gpt-6-sol`, 推理强度为 `xhigh`; 用户指定值优先, 无需本地执行子代理配置.
- 创建执行子代理时设置 `agent_type: "default"`, 显式传入 `model` 和 `reasoning_effort`. 使用 `spawn_agent` 创建任何子代理时始终设置 `fork_turns: "none"`, 不复制全部或部分会话历史, 在任务消息中显式交接上下文.
- Codex 未提供所需工具或参数时, 说明限制并由主代理执行, 保持会话启用状态; 不静默替换模型或改用历史继承.
- 按交付物划分能独立开展的任务, 不设固定角色流水线. 主代理推进不重复的决策或验收准备; 没有独立工作时不为并行制造任务.

## 交接与验收

- 任务消息包含目标, 工作目录, 文件与职责范围, 已有改动, 已确认结论与用户决定, 必要约束和完成条件. 提供相关证据的位置, 将调查路径与实现选择交给执行者; 执行者不得再创建子代理.
- 同一共享文件或构建状态只允许一个写入者, 保留既有改动. 补充与返工优先复用原实例并交接增量上下文; 接管前确认原执行者及相关进程已停止写入.
- 执行者持续完成实现, 所需运行或画面检查及缺陷修复, 不在首版实现后等待例行批准. 缺失关键信息, 改动冲突或超出授权范围时报告依据并继续独立工作.
- 交付实际结果, 关键文件或证据, 验证结论及未完成项. 主代理核对产物是否满足完成条件, 只补查疑点与验证缺口, 确认委派工作已完成或终止并处理遗留影响后交付.
